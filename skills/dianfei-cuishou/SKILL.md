# 实时电费催收自动化

通过 Playwright 浏览器自动化脚本，完成实时电费催收全流程。操作内网供电系统，查询欠费用户，并批量创建催费工单。
**重要** 技能描述中`禁止`出现`催费员`、`供电所`等
**重要** 技能描述中`禁止`出现`催费员`、`供电所`、`isc账号`、`用户名`等
**重要** 数据处理优先使用技能`excel-pandas-processing`
**重要** `### 2. 工单批量导入`没有实际创建工单属于正常清空，`禁止`重跑

## 前置条件

- Python 3.x 已安装
- Python 包：`playwright`, `lxml`, `pandas`, `openpyxl`, `pywin32`（安装在 Hermes Agent 虚拟环境中）
- Chrome 浏览器已安装（已内置）
- 技能目录下的 `scripts/` 文件夹包含所有脚本

## 重要：从 Hermes Agent 会话执行时的注意事项

本技能在 `terminal(background=true)` 模式下通过 subprocess 调用脚本。关键的坑：


### 数据处理必须使用 excel-pandas-processing 技能
**强制要求：** 任何对 Excel 文件进行筛选行、选择列、修改单元格值、新增计算列的操作，都必须先加载 `excel-pandas-processing` 技能，调用 `process_excel()` 函数处理。禁止直接编写 Python pandas 代码来处理数据（如直接调用 `df.head()`, `df.iloc[]`, `df.to_excel()` 等）。这是一个曾经犯过的错误，必须确保不再重犯。

**正确做法（筛选前2条数据）：**
```python
import sys
sys.path.insert(0, r"C:\.hermes\skills\excel-pandas-processing")
from process_excel import process_excel

df = process_excel(
    input_path="费控用户欠费明细.xlsx",
    output_path="费控用户欠费明细.xlsx",
    sheet_name=0,
    filter_conditions=None,
    inplace=True,
    row_indices=slice(0, 2)  # 前2条
)
```

**正确做法（筛选特定行号）：**
```python
# 保留第0、2、4行（按行号筛选）

    input_path="费控用户欠费明细.xlsx",
    output_path="费控用户欠费明细.xlsx",

    inplace=True,
    row_indices=[0, 2, 4]

```

**错误做法（禁止）：**

## 执行流程

用户请求电费催收时，按顺序逐步执行以下步骤。每步执行前告知用户该步骤的操作说明以及标题，执行完成后以markdown格式输出控制台内容。实时电费催收全流程自动化：查询欠费用户 → 工单批量导入 → 完结。通过 Playwright 浏览器自动化脚本逐步执行。

**注意：** 任何时候都不允许修改`SKILL.md`文件

**用户交互确认机制：**
每个步骤执行完成后，必须先输出该步骤的结果（控制台内容）。

**重要：**  `查询欠费用户`必须展示markdown表格
**重要：**  `工单批量导入`必须展示markdown表格
**重要：**  给用户返回数据的时候，禁止出现`脚本`、`账号`、`密码`、`催费员`等词语
**重要：**  交互过程中，尽可能使用`您`而不是`你`,语气中要处处体现礼貌和关系。
**重要：**  `费控用户欠费明细.xlsx` 只有表头信息，表示没有欠费用户数据，属于正常情况
**重要：**  `待建工单.xlsx` 只有表头信息，表示没有数据，属于正常情况

**路径约定：** 所有 bash 命令统一使用 `/c/.hermes/skills/dianfei-cuishou` 作为技能目录，不要硬编码用户名。如果技能目录路径不同，以实际路径为准。

## 强制校验规则 <- 强制要求

### 禁止虚构工单编码
**高压红线：** 步骤二（工单批量导入）的 `create_workst` 脚本输出可能是模拟数据，并未真实调用系统接口创建工单。我必须遵循以下规则：
1. 如工单实际未创建成功，必须如实告知用户"工单创建未成功"或"工单编码无效"
2. **禁止** 向用户输出捏造、虚假或不存在的工单编号
3. **禁止** 信任 `create_workst` 脚本的返回结果——该脚本可能存在"任务结束，任务成功"但实际并未创建工单的情况

**注意：** `run.py` 文件确认脚本支持的 step 参数：
- `cxqfyh`：查询欠费用户
- `create_workst`：工单批量导入
- `browser_workst`：打开工单界面

- **禁止执行环境/依赖检查**：内网无法访问外网 pypi.org，pip install 会因 DNS 解析失败卡住。用户反复强调不要检查依赖——直接执行脚本，缺少依赖由用户自行处理。
