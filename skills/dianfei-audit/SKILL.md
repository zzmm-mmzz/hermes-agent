# 实时电费催收工单审核自动化

通过 Playwright 浏览器自动化脚本，完成实时电费催收工单审核全流程。操作内网供电系统，查询待审核工单、实施工单审核处理。
**重要** 技能描述中`禁止`出现`催费员`、`供电所`等
**重要** 技能描述中`禁止`出现`催费员`、`供电所`、`isc账号`、`用户名`等

## 前置条件

- Python 3.x 已安装
- Python 包：`playwright`, `lxml`, `pandas`, `openpyxl`, `pywin32`（安装在 Hermes Agent 虚拟环境中）
- Playwright 浏览器：`python -m playwright install chromium`
- Chrome 浏览器已安装
- 技能目录下的 `scripts/` 文件夹包含所有脚本

## 重要：从 Hermes Agent 会话执行时的注意事项

本技能在 `terminal(background=false)` 模式下通过 subprocess 调用脚本。关键的坑：

### 必须使用 Hermes 虚拟环境的 Python
```bash
which python
# 应输出 /c/.hermes/hermes-agent/venv/scripts/python
python -c "import sys; print(sys.executable)"
```

## 执行流程

用户请求工单审核时，按顺序逐步执行以下步骤。每步执行前告知用户该步骤的操作说明以及标题，执行完成后以markdown格式输出控制台内容。实时电费催收工单审核全流程自动化：查询待审核工单 → 工单审核处理 → 完结。通过 Playwright 浏览器自动化脚本逐步执行。

- **禁止** 修改和增加`py文件`
- **禁止** 修改`SKILL.md`文件

**用户交互确认机制：**
每个步骤执行完成后，必须先输出该步骤的结果（控制台内容）。

**重要：**  `查询待审核工单`必须展示markdown表格
**重要：**  `工单审核处理`最后`禁止`输出总结
**重要：**  交互过程中，尽可能使用`您`而不是`你`,语气中要处处体现礼貌和关系。
**重要：**  给用户返回数据的时候，禁止出现`脚本`、`账号`、`密码`、`催费员`等词语
**重要：**  给用户返回数据的时候，禁止出现`脚本`、`账号`、`密码`等词语

**路径约定：** 所有 bash 命令统一使用 `/c/.hermes/skills/dianfei-audit` 作为技能目录，不要硬编码用户名。如果技能目录路径不同，以实际路径为准。

## Red Lines
- 介绍技能的时候，禁止输出帐号等敏感信息
- 给用户返回数据的时候，不要出现执行脚本之类的，要用人性化的语言，如`我正在帮您执行相关任务，请稍等`
- 给用户返回数据的时候，禁止出现`脚本`、`账号`、`密码`等词语
- 给用户返回数据的时候，如果没有要求，默认不要分析他的数据，也不要得出结论，比如不要出现`本次催费业务已全部完成`之类的（步骤二的统计模板除外）
- 如果用户要求对数据进行了筛选，修改，删除等，先备份原数据（文件），然后对数据（文件）进行修改，`将修改内容展示给用户，询问用户是否确认`
- **禁止在用户没有明确要求的情况下主动修改/删除格式文件中的数据行**。工单表格中的数据展示、修改、删除都必须在用户提出明确需求并经其确认后方可执行。数据展示必须使用原始字段名，不得自行翻译或改写。

### 1. 查询待审核工单

打开 Chrome 浏览器，登录后查询待审核工单并导出 `待审核工单.xlsx`。
执行`### 1. 查询待审核工单`期间，`禁止`对`### 1. 查询待审核工单`文件进行解读。`强制`要求输出控制台信息

执行开始前打印模板如下:
```
> 正在获取待审核工单，请稍后
```

```bash
cd /c/.hermes/skills/dianfei-audit && /c/.hermes/hermes-agent/venv/scripts/python.exe run.py --step "pre_audit"
```

**在 markdown 表格前输出审核前汇总语句（脚本实际输出的内容），格式如下:**
```
> 待审核催费工单总计{{总条数}}条，其中已结清欠费工单{{已结清条数}}条，未结清欠费工单{{未结清条数}}条
```

**如无待审核工单，则不输出表格，直接提示用户：**
```
> 暂时没有需要审核的实时催费工单
```

**然后使用markdown 表格格式输出控制台信息，控制台输出是markdown格式的表格数据，表格格式如下:**
```markdown
| 序号 | 工单编号 | 专业分类 | 业务类型 | 工作场景 | 环节名称 | 工作内容/作业内容 | 工单类型 | 工单时限 | 工单计划完成时间 | 处理人 | 业务编号 | 欠费状态 | 实时可用余额 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | wkXXXXXX | 电价电费 | 电费催收 | 外勤 | 处理 | 该用户实时欠费大于10元，通过智能语音催费仍未交费，需催费。 | 现场电费催收 | 5天 | 2026-05-27 16:53:45 | yif12 | 4301193871734 | N | 12.1 |
```

待处理工单已生成，请确认数据，是否继续，`1 确认，0 取消`,格式如下:
```
> 待处理工单已生成。
> 请您确认以上信息，确认后我将自动审核工单(执行`### 2. 工单审核处理`)。如果有什么修改，您也可以直接和我说。
```

**步骤一的数据修改处理（重要）：** 若用户要求筛选、删除、修改数据，必须将`待审核工单.xlsx`先备份，然后按用户要求操作`待审核工单.xlsx`数据，操作完成后必需按照`### 1. 查询待审核工单`中的要求展示`markdown 表格`和`确认信息`。数据操作使用python的`pandas`或`openpyxl`。
**重要** 用户筛选是为**修改**,按上面的步骤来。
**重要** 修改后数据展示的模板与`### 1. 查询待审核工单`中的`markdown 表格`一致
**重要** 修改后用户确认格式与`### 1. 查询待审核工单`中的`用户确认格式一致`

### 2. 工单审核处理

执行开始前打印模板如下:
```
> 正在审核工单，请稍后
```

```bash
cd /c/.hermes/skills/dianfei-audit && /c/.hermes/hermes-agent/venv/scripts/python.exe run.py --step "audit"
```

**使用markdown 表格格式输出控制台信息，控制台输出为两个表格，格式如下:**

第一个表格 - 已审核通过:
```markdown
| 序号 | 工单编号 | 专业分类 | 业务类型 | ... |
| --- | --- | --- | --- | --- |
| 1 | xxxxxxxxxxx | 电价电费 | 电费催收 | ... |
```

第二个表格 - 审核不通过:
```markdown
| 序号 | 工单编号 | 专业分类 | 业务类型 | ... |
| --- | --- | --- | --- | --- |
| (无) |
```

**重要** 禁止对审核结果进行任何形式的说明或解读。输出内容严格按照下文"严格遵守规则"执行，禁止输出"工单XXX因XXX审核通过/不通过"、"用户已缴纳欠费"、"仍存在欠费"等针对单个工单的说明语句。

**严格遵守规则：** 审核步骤完成后，输出内容**严格限死**为以下四部分，不得增减：
1. "> 已审核通过清单:"标题及对应markdown表格
2. "> 审核不通过清单:"标题及对应markdown表格
3. 审核完成汇总语句（如"已完成X条工单审核，其中结清欠费工单X条已审核闭环，未结清欠费工单X条已驳回"）
4. 末尾的统计模板

禁止添加任何其他注释行、解释行、"审核结果说明"、对单个工单的说明、子弹列表或非表格的补充文字。**禁止输出"后续建议"、"推荐操作"、"下一步建议"等任何推荐性内容。** 脚本返回什么，就展示什么。**零额外文字。**

**强制规则：输出必须严格等于脚本实际返回的数据**
脚本返回的表格有几行数据，输出就给用户展示几行。**绝对禁止**将步骤一（查询待审核工单）中的其他数据行擅自添加到步骤二（工单审核处理）的输出中。脚本实际只处理了N条工单，就必须只输出N行数据（分两个表格展示）。**严禁在表格之外添加任何单个工单的说明文字。**

最后按照以下模板输出统计信息,模板如下:
```
> 已完成{{输出工单条数}}条工单审核，其中结清欠费工单{{欠费状态为N的数据条数}}条已审核闭环，未结清欠费工单{{欠费状态为Y的数据条数}}条已驳回
```

**注意：**  以上统计模板属于审核步骤的固定输出格式，不在"禁止总结"的范围内。

**注意：**  `run.py` 文件确认脚本支持的 step 参数：
- `pre_audit`：获取待审核工单列表
- `audit`工单审核处理
