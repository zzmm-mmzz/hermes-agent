# 个人重点事项 - 到点提醒功能接口文档

> 服务：mcp-eip-mock（EIP 门户集成服务）
> 端口：8200
> 文件：server.py
> 更新日期：2026-08-12

## 一、功能概述

个人重点事项新增"到点提醒"能力：

1. 添加重点事项时可指定提醒时间 `remindTime`
2. 服务端后台协程每 20 秒扫描一次，到点自动把 `pending` 标记为 `sent`（进入"待确认提醒"列表）
3. 前端定时轮询 `GET /api/reminders/pending` 拉取到点提醒并展示
4. 用户确认后调 `POST /api/reminders/ack`，状态变为 `acked`，不再返回

不传 `remindTime` 时行为与旧版完全一致（向后兼容）。

## 二、数据模型变更

每条重点事项新增两个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| remindTime | string | 提醒时间，格式 `YYYY-MM-DD HH:MM:SS`，为空表示不提醒 |
| remindStatus | string | 提醒状态：`pending`（等待提醒）/ `sent`（已到点，待确认）/ `acked`（已确认）。未设置 remindTime 时为空字符串 |

## 三、接口清单

### 1. POST /api/personal-notes 添加重点事项（已扩展）

请求体：

```json
{
  "title": "本月电费催收待办",
  "content": "3月电费催收工单待处理，共23户",
  "source": "待办",
  "extra": {},
  "remindTime": "2026-08-12 15:00:00"
}
```

参数说明：

| 参数 | 必填 | 说明 |
|------|------|------|
| title | 是 | 标题，非空校验 |
| content | 否 | 详细内容 |
| source | 否 | 来源（邮件/待办/任务等） |
| extra | 否 | 任意透传数据 |
| remindTime | 否 | 提醒时间 `YYYY-MM-DD HH:MM:SS`；格式非法返回 code=1；传过去的时间立即触发提醒 |

响应：

```json
{
  "code": 0,
  "message": "重点事项已保存",
  "data": {
    "id": "NOTE17865021390001",
    "title": "本月电费催收待办",
    "content": "3月电费催收工单待处理，共23户",
    "source": "待办",
    "extra": {},
    "remindTime": "2026-08-12 15:00:00",
    "remindStatus": "pending",
    "createTime": "2026-08-12 14:00:00",
    "updateTime": "2026-08-12 14:00:00"
  }
}
```

### 2. GET /api/personal-notes 列表查询（已扩展）

参数：`keyword`（模糊搜索）、`pageSize`、`pageNo`。返回每条带 `remindTime` 和 `remindStatus` 字段。

### 3. GET /api/reminders/pending 待确认提醒列表（新增）

前端轮询接口。返回所有已到点（sent）且用户未确认（未 acked）的提醒。

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": "NOTE17865021390001",
      "title": "本月电费催收待办",
      "content": "3月电费催收工单待处理，共23户",
      "source": "待办",
      "remindTime": "2026-08-12 15:00:00",
      "remindStatus": "sent"
    }
  ]
}
```

### 4. POST /api/reminders/ack 确认提醒（新增）

请求体：`{"id": "NOTE17865021390001"}`

把 `sent` 改为 `acked`，确认后不再出现在 pending 列表。id 不存在返回 code=1。

## 四、前端接入示例（30 秒轮询）

```javascript
// 页面加载后启动轮询
setInterval(async () => {
  try {
    const res = await fetch('/api/reminders/pending');
    const data = await res.json();
    if (data.code === 0 && data.data && data.data.length > 0) {
      data.data.forEach(item => showReminder(item));  // 弹提醒/亮角标
    }
  } catch (e) { /* 网络异常忽略，下轮重试 */ }
}, 30000);  // 30 秒一次

// 用户点击"确认"后
async function ackReminder(id) {
  await fetch('/api/reminders/ack', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ id })
  });
}
```

要点：

- 30 秒延迟对提醒场景足够，想更实时可缩到 10 秒
- 用户不在线时提醒一直留在待确认列表，下次打开页面立即拉到，不丢失
- 页面切换后台 tab 时浏览器可能节流 setInterval，回到前台会补执行，正好符合"回来就看到提醒"

## 五、MCP 工具（新增两个）

| 工具名 | 说明 |
|--------|------|
| add_personal_note | 原工具，input_schema 新增 remindTime 参数 |
| list_due_reminders | 查询待确认提醒列表（等同 GET /api/reminders/pending） |
| ack_reminder | 确认提醒（等同 POST /api/reminders/ack） |

调用方式：`POST /tools/<工具名>` 或 `POST /mcp`（JSON-RPC）。

## 六、服务端实现说明

| 改动点 | 位置 | 说明 |
|--------|------|------|
| remindTime 解析校验 | _handle_add_personal_note | 格式非法返回 code=1 不落库 |
| reminder_loop 协程 | main() 前定义 | 每 20 秒扫描，pending 且到点 → sent，防重复 |
| GET /api/reminders/pending | 路由分发 | 返回 sent 且未 acked 列表 |
| POST /api/reminders/ack | 路由分发 | 按 id 改状态，不存在报错 |
| MCP 工具注册 | _register_tools | 新增 list_due_reminders / ack_reminder |
| 启动后台任务 | main() | create_task(reminder_loop()) |

边界情况：

- remindTime 为过去时间：接受并立即触发提醒
- 重复触发：触发即标记 sent，天然防重
- 删除事项：提醒跟随消失（DELETE 逻辑未改动）
- 并发：asyncio 单线程事件循环，无锁问题
- 存储：内存列表，服务重启数据清空（mock 阶段固有限制）
